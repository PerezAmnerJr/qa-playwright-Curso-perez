# DR-001 — Reporte de defecto simulado

**Fecha:** 29 de agosto de 2026
**Reportado por:** Amner Alberto Pérez Marroquín
**Módulo afectado:** Carrito de compras — badge del ícono del carrito
**Test relacionado:** `Comparar estados antes y después de una acción` (tests/clase07.spec.ts)

## Título

El badge del carrito no actualiza a "2" después de agregar un solo producto.

## Severidad y prioridad

- **Severidad:** Media
- **Prioridad:** Media

Lo marco como media porque no impide comprar ni rompe el flujo completo, pero si el conteo del carrito estuviera mal en un caso real, el usuario podría confundirse sobre cuántos productos lleva agregados.

## Pasos para reproducir

1. Ir a https://www.saucedemo.com
2. Iniciar sesión con `standard_user` / `secret_sauce`
3. Verificar el estado inicial del carrito (sin badge visible)
4. Hacer clic en "Add to cart" del primer producto del inventario
5. Verificar el texto del badge del carrito

## Resultado esperado

El badge debería mostrar **"2"** después de agregar el producto.

## Resultado obtenido

El badge muestra **"1"**, que es el número real de productos agregados en ese momento.

## Evidencia

Al correr el test con la aserción forzada (`toHaveText('2')`), Playwright generó automáticamente:

- Un **screenshot** del estado exacto donde el test falló, mostrando el badge con el valor real ("1") junto al mensaje de error de la aserción.
- Un **video** de la ejecución completa hasta el punto del fallo.
- Un **trace** navegable que muestra paso a paso las acciones del test (login, clic en Add to cart, verificación del badge).

Ambos se ven en el reporte HTML corriendo `npx playwright show-report`, en el test fallido "Comparar estados antes y después de una acción".

## Nota

Este defecto fue **simulado a propósito** para el laboratorio de la Clase 07: se cambió intencionalmente el valor esperado en el test de `'1'` a `'2'` para observar cómo Playwright captura evidencia de un fallo. Después de tomar la evidencia, el valor se revirtió a `'1'` y el test volvió a pasar (4/4 passed), confirmando que la aplicación en realidad se comporta correctamente y el "defecto" no era real.

Esto conecta con la teoría de la Clase 07 sobre Error, Defecto y Fallo: el error fue mío al escribir mal la aserción, el defecto quedó en el código del test (no en saucedemo), y el fallo se manifestó al ejecutar la suite.
